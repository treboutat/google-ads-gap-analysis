# Google Ads Gap Analysis

Find the search terms in a Google Ads account that deserve to become keywords. Hand it the last quarter of account data and get back one review workbook: what drives value today, the GAP keywords worth adding (each with a purpose and a destination), new RSAs built from your proven headlines and descriptions, scoped negative proposals, and clean Google Ads Editor CSVs for whatever you approve.

It judges every candidate against mature conversions and the way the campaign actually bids, not raw conversion counts. It never changes the account.

## Who it's for
Anyone running an established Google Ads Search account who wants to grow from demand the account already reaches: searches that convert but aren't keywords, keywords that exist only paused, terms a current negative is quietly blocking, and winning themes stuck behind a generic ad and page.

**As a plain SOP:** read `SKILL.md` end to end. It's a complete procedure even if you never run it through Claude.

## What you provide
1. Account data for the last 90 days, either GAQL results (queries in `references/gaql-queries.md`) or Google Ads UI exports: campaigns with bid strategies, the search terms report with zero-click rows, the keyword report with keyword, ad-group and campaign status, conversion actions, current negatives with their match types and list attachments, and asset performance.
2. Your offer: what you sell, what you don't, where you serve, and your brand and competitor strategy.
3. The outcome that matters (qualified lead, booked call, customer), what you can afford per outcome, and how long conversions take to arrive.
4. Any exclusions someone made on purpose, so the analysis doesn't undo them.

It works with partial data and says what it couldn't check.

## What you get
- A review workbook: Read Me with the recommendation and coverage, keyword value benchmark, GAP keywords with proof rows, candidates considered and not added, RSA build with character checks, negative proposals grouped into families with a reviewer verdict column, and a QA tab.
- Clean Editor CSVs carrying only importable fields. Everything new is Paused, and the negatives file (generated by a script) contains only rows you marked Exclude.
- A low/high lift range per theme, labelled as platform conversion value, not revenue.

## Files
- `SKILL.md`: the workflow
- `references/method-rules.md`: the judgment rules (search-term review, keyword additions, negatives, ads)
- `references/gaql-queries.md`: every query, with the join and coverage traps to avoid
- `references/workbook-spec.md`: the workbook and upload file layout
- `references/asset-selection.md`: choosing proven assets for new RSAs
- `scripts/`: load UI or GAQL exports, resolve every current negative to its scope, surface GAP candidates, join conversion actions without double counting, check negative conflicts, validate RSA limits, and export approved negatives. The workbook and the keyword and RSA files are built by Claude from the spec; the scripts handle the parts where counting or matching errors are easy to make
- `tests/`: worked example and edge cases (blocked and paused keywords, immature and stage-valued conversions, routing), plus unit tests for the scripts (`python3 -m unittest discover -s tests/scripts`)
